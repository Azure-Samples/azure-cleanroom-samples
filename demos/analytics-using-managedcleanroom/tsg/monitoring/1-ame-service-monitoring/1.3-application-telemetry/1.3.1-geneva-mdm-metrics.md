# 1.3.1 Geneva/MDM Metrics (AME Standard)

## Overview

Custom application metrics emitted by ACCR services via OTLP → Geneva → Kusto. These are the **primary engineering metrics** for measuring service health, performance, and reliability.

**Pipeline (already built):**
```
App Code (OpenTelemetry SDK)
  → OTLP gRPC → ILB:4317
    → Geneva DaemonSet (mdsd)
      → Geneva Storage
        → Kusto (Geneva→Kusto by Vaiddhe/Yash)
          → Dgrep / Dashboards / Alerts
```

The transport layer (OTLP → ILB → Geneva → Kusto) is **done**. What's needed now is **instrumenting the application code** to emit these metrics.

The metrics listed in the following sections are **in addition to** the existing 26 metrics. They focus on:

### OTel Traceability Requirement

All new metrics **must** include `correlationId` and `clientRequestId` as labels/dimensions to enable end-to-end traceability across services. These should be propagated from the incoming ARM request headers (`x-ms-correlation-request-id`, `x-ms-client-request-id`) and attached to every metric recorded during that request's lifecycle.

## Implementation Plan

### Step 1: Add OpenTelemetry SDK to Each Service

The services already have OTel metric infrastructure in place:
- `MeterMetricsEmitter` / `IMetricsEmitter` wrapping `System.Diagnostics.Metrics.Meter` (meter name: `Microsoft.Azure.CleanRoomService`)
- Geneva + OTLP + Console exporters configured in each service via `OpenTelemetryUtilities`
- 26 existing metrics auto-generated from XML codegen

New metrics should be added to the same meter and follow the existing pattern. Ensure `correlationId` and `clientRequestId` are propagated as labels.

Example (.NET / C#):
```csharp
using System.Diagnostics.Metrics;

public static class AccrMetrics
{
    private static readonly Meter s_meter = new("ACCR.RP");
    
    private static readonly Histogram<double> s_createDuration = 
        s_meter.CreateHistogram<double>("CollaborationCreate.Duration", "ms");
    
    private static readonly Counter<long> s_createSuccess = 
        s_meter.CreateCounter<long>("CollaborationCreate.Success");
    
    private static readonly Counter<long> s_createFailure = 
        s_meter.CreateCounter<long>("CollaborationCreate.Failure");
    
    public static void RecordCreateDuration(double durationMs, string region, string result, 
        string correlationId, string clientRequestId)
    {
        s_createDuration.Record(durationMs, 
            new("region", region), 
            new("result", result),
            new("correlationId", correlationId),
            new("clientRequestId", clientRequestId));
    }
    
    public static void RecordCreateSuccess(string region, string correlationId, string clientRequestId)
    {
        s_createSuccess.Add(1, 
            new("region", region),
            new("correlationId", correlationId),
            new("clientRequestId", clientRequestId));
    }
    
    public static void RecordCreateFailure(string region, string reason, 
        string correlationId, string clientRequestId)
    {
        s_createFailure.Add(1, 
            new("region", region), 
            new("failureReason", reason),
            new("correlationId", correlationId),
            new("clientRequestId", clientRequestId));
    }
}
```

### Step 2: Instrument Workflow Tasks

Add metric recording at the start/end of each workflow task:
```csharp
public async Task ExecuteTaskAsync(string taskName, string workflowName)
{
    var sw = Stopwatch.StartNew();
    try
    {
        await RunTaskAsync();
        sw.Stop();
        AccrMetrics.RecordTaskDuration(sw.ElapsedMilliseconds, taskName, workflowName, "Success");
        AccrMetrics.RecordTaskSuccess(taskName, workflowName);
    }
    catch (Exception ex)
    {
        sw.Stop();
        AccrMetrics.RecordTaskDuration(sw.ElapsedMilliseconds, taskName, workflowName, "Failure");
        AccrMetrics.RecordTaskFailure(taskName, workflowName, ex.GetType().Name);
        throw;
    }
}
```
