# 1.3.2 Structured Logging (Geneva/Kusto)

## Overview

Emit **structured log entries** from all 3 AME services with a consistent schema. This replaces unstructured text logs with queryable, correlated entries in Kusto.

**Without structured logging:** "Grep through stdout for error messages" — slow, no correlation, no aggregation.

**With structured logging:** `CleanRoomOperations | where collaborationName == "ashank110" | where level == "Error"` — instant, filterable, joins across services.

## Current State

**Status: TBD** — Exact schema needs to be finalized. Services currently emit unstructured logs to stdout (captured by Container Insights if enabled).

### Field Definitions

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `timestamp` | datetime | Yes | UTC timestamp |
| `service` | string | Yes | `RP`, `Frontend`, or `ConsortiumManager` |
| `operationId` | string | Yes (RP) | ARM operation ID — allows joining with ARM Activity Log |
| `collaborationName` | string | When applicable | Customer's collaboration name |
| `subscriptionId` | string | When applicable | Customer's Azure subscription |
| `tenantId` | string | When applicable | Customer's AAD tenant |
| `resourceGroup` | string | When applicable | Customer's resource group |
| `taskName` | string | When applicable | Workflow task (e.g., `CreateClusterTask`) |
| `workflowName` | string | When applicable | Parent workflow (e.g., `CreateClusterWorkflow`) |
| `level` | string | Yes | `Information`, `Warning`, `Error` |
| `message` | string | Yes | Human-readable message |
| `exceptionType` | string | On error | Exception class name |
| `exceptionMessage` | string | On error | Exception message (sanitized — no secrets) |
| `durationMs` | long | When applicable | Operation duration in milliseconds |
| `correlationId` | string | Yes | Unique ID to correlate across services |
| `region` | string | Yes | Azure region |
| `environment` | string | Yes | `Test`, `Canary`, `Prod` |

## Implementation Plan

### Step 1: Define Logging Interface

```csharp
public interface IAccrLogger
{
    void LogOperation(
        string taskName,
        string workflowName,
        string collaborationName,
        string subscriptionId,
        string tenantId,
        string message,
        LogLevel level = LogLevel.Information,
        long? durationMs = null,
        Exception? exception = null);
}
```

### Step 2: Implement with OpenTelemetry Logging

```csharp
public class AccrLogger : IAccrLogger
{
    private readonly ILogger _logger;

    public void LogOperation(
        string taskName, string workflowName, string collaborationName,
        string subscriptionId, string tenantId, string message,
        LogLevel level, long? durationMs, Exception? exception)
    {
        using var scope = _logger.BeginScope(new Dictionary<string, object>
        {
            ["service"] = "RP",
            ["taskName"] = taskName,
            ["workflowName"] = workflowName,
            ["collaborationName"] = collaborationName,
            ["subscriptionId"] = subscriptionId,
            ["tenantId"] = tenantId,
            ["durationMs"] = durationMs ?? 0,
            ["correlationId"] = Activity.Current?.Id ?? Guid.NewGuid().ToString(),
            ["region"] = Environment.GetEnvironmentVariable("REGION") ?? "unknown",
            ["environment"] = Environment.GetEnvironmentVariable("ENVIRONMENT") ?? "unknown"
        });

        if (exception != null)
            _logger.Log(level, exception, message);
        else
            _logger.Log(level, message);
    }
}
```

### Step 3: Integrate into Workflow Tasks

```csharp
public async Task ExecuteCreateClusterAsync(CollaborationContext ctx)
{
    var sw = Stopwatch.StartNew();
    _logger.LogOperation(
        "CreateClusterTask", "CreateClusterWorkflow",
        ctx.CollaborationName, ctx.SubscriptionId, ctx.TenantId,
        "Starting cluster creation");
    try
    {
        await CreateClusterAsync(ctx);
        sw.Stop();
        _logger.LogOperation(
            "CreateClusterTask", "CreateClusterWorkflow",
            ctx.CollaborationName, ctx.SubscriptionId, ctx.TenantId,
            "Cluster creation completed",
            durationMs: sw.ElapsedMilliseconds);
    }
    catch (Exception ex)
    {
        sw.Stop();
        _logger.LogOperation(
            "CreateClusterTask", "CreateClusterWorkflow",
            ctx.CollaborationName, ctx.SubscriptionId, ctx.TenantId,
            "Cluster creation failed",
            LogLevel.Error, sw.ElapsedMilliseconds, ex);
        throw;
    }
}
```

## Example Kusto Queries

```kql
// Failed operations in last 24h by task
CleanRoomOperations
| where Timestamp > ago(24h)
| where Level == "Error"
| summarize Count=count(), Reasons=make_set(ExceptionType) by TaskName, Region
| order by Count desc

// Collaboration lifecycle for a specific customer
CleanRoomOperations
| where CollaborationName == "ashank110"
| where WorkflowName == "CreateClusterWorkflow"
| project Timestamp, TaskName, Level, DurationMs, Message
| order by Timestamp asc

// Task duration percentiles over last 7 days
CleanRoomOperations
| where Timestamp > ago(7d)
| where DurationMs > 0
| summarize p50=percentile(DurationMs, 50), p95=percentile(DurationMs, 95), p99=percentile(DurationMs, 99) by TaskName
| order by p95 desc

// Cross-service correlation
CleanRoomOperations
| where CorrelationId == "<guid>"
| project Timestamp, Service, TaskName, Level, Message
| order by Timestamp asc
```

## Security Considerations

- **Never log secrets** (keys, tokens, connection strings)
- **Sanitize exception messages** — strip any embedded credentials
- **PII handling** — subscriptionId and tenantId are considered customer identifiers; follow data retention policies
- **Correlation IDs** — use OpenTelemetry trace context propagation, not custom GUIDs where possible
