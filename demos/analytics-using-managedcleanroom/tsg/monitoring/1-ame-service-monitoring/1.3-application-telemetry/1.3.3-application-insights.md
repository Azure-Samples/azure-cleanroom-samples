# 1.3.3 Application Insights (Optional, for Frontend Service)

## Overview

Application Insights provides APM (Application Performance Monitoring) capabilities beyond what Geneva/MDM offers. It's particularly useful for the **Frontend Service** because it's the customer-facing endpoint where dependency tracking and live debugging are most valuable.

## Current State

**Status: TBD / Not Planned** — Optional. Geneva/MDM (Section 1.3.1) covers most of the same ground. Only pursue if the team needs live debugging or auto-dependency tracking that Geneva doesn't provide.

## What Application Insights Would Add

| Capability | Geneva/MDM | App Insights | Value-Add |
|-----------|-----------|-------------|-----------|
| Custom metrics | ✅ | ✅ | No added value |
| Structured logging | ✅ | ✅ | No added value |
| Auto dependency tracking | ❌ | ✅ | Tracks Frontend → CCF, Frontend → Analytics endpoint automatically |
| Request/response tracing | Partial | ✅ | Full distributed trace with waterfall view |
| Failed dependency alerts | Manual | ✅ Auto | Auto-detects when analytics endpoint is unreachable (the NRMS NSG issue) |
| Live Metrics Stream | ❌ | ✅ | Real-time request rate, failure rate, CPU — useful during incidents |
| Application Map | ❌ | ✅ | Visual dependency graph |
| Smart Detection | ❌ | ✅ | ML-based anomaly detection |

## When to Implement

Consider implementing if:
- CSS needs real-time debugging during customer escalations
- The team needs auto-discovery of dependency failures (like the NRMS NSG blocking issue)
- A portal Insights blade for Collaborations is planned (App Insights backs the portal experience)

Skip if:
- Geneva/MDM metrics + Kusto queries are sufficient for debugging
- The team prefers Dgrep/Kusto over Azure Portal

## Implementation (If Decided)

### Step 1: Add App Insights SDK

```csharp
// Program.cs or Startup.cs
builder.Services.AddApplicationInsightsTelemetry(options =>
{
    options.ConnectionString = configuration["APPLICATIONINSIGHTS_CONNECTION_STRING"];
});

// Enable OpenTelemetry bridge (so metrics go to both Geneva AND App Insights)
builder.Services.AddOpenTelemetry()
    .WithTracing(tracing => tracing
        .AddAspNetCoreInstrumentation()
        .AddHttpClientInstrumentation()
        .AddOtlpExporter()                    // → Geneva (existing)
        .AddAzureMonitorTraceExporter());     // → App Insights (new)
```

### Step 2: Configure Connection String via EV2

Add `APPLICATIONINSIGHTS_CONNECTION_STRING` to Frontend ScopeBindings.json, similar to `__OTEL_ENDPOINT__`.
