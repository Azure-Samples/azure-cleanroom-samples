# 1.5 Container Insights

## Overview

Container Insights is an AKS add-on that collects container-level telemetry: stdout/stderr logs, pod events, resource usage. It provides the **"what are my pods doing?"** view that platform metrics (Section 1.1) and resource logs (Section 1.4) don't cover.

## Current State

**Status: Planned** — Not yet enabled on AME AKS clusters.

## What Container Insights Collects

| Table | What | Use Case |
|-------|------|----------|
| `ContainerLogV2` | stdout/stderr from all containers | Application log search (before structured logging is implemented) |
| `KubeEvents` | Pod creation, deletion, failures, OOMKilled | Detect crash loops, OOM, scheduling failures |
| `KubePodInventory` | Pod state tracking over time | Track pod lifecycle, restarts |
| `Perf` | CPU/memory per container | Resource usage analysis, right-sizing requests/limits |
| `KubeNodeInventory` | Node state and labels | Node health tracking |

## Implementation Plan

### Step 1: Enable Container Insights via AKS Add-on

```json
{
  "type": "Microsoft.ContainerService/managedClusters",
  "properties": {
    "addonProfiles": {
      "omsagent": {
        "enabled": true,
        "config": {
          "logAnalyticsWorkspaceResourceID": "[resourceId('Microsoft.OperationalInsights/workspaces', parameters('workspaceName'))]",
          "useAADAuth": "true"
        }
      }
    }
  }
}
```

### Step 2: Configure Data Collection Rule (DCR)

Control what gets collected to manage costs:

```json
{
  "type": "Microsoft.Insights/dataCollectionRules",
  "properties": {
    "dataSources": {
      "extensions": [
        {
          "name": "ContainerInsightsExtension",
          "streams": [
            "Microsoft-ContainerLogV2",
            "Microsoft-KubeEvents",
            "Microsoft-KubePodInventory",
            "Microsoft-Perf",
            "Microsoft-KubeNodeInventory"
          ],
          "extensionSettings": {
            "dataCollectionSettings": {
              "interval": "1m",
              "namespaceFilteringMode": "Include",
              "namespaces": [
                "cleanroom-ns",
                "frontendns",
                "consortiummanager-ns",
                "geneva"
              ],
              "enableContainerLogV2": true
            }
          }
        }
      ]
    }
  }
}
```

**Important:** Filter to only relevant namespaces — skip `kube-system`, `default`, etc. to control costs.

### Step 3: Configure Cost-Effective Retention

```kql
// Set ContainerLogV2 to Basic tier (cheaper, 8-day retention)
.alter table ContainerLogV2 policy retention "{'SoftDeletePeriod': '8.00:00:00'}"
```

Once structured logging (Section 1.3.2) is implemented, ContainerLogV2 becomes less critical — it's a bridge until custom logs flow through Geneva.

## Key Alert Rules

| Alert | Table | Condition | Severity |
|-------|-------|-----------|----------|
| Pod CrashLoop | KubeEvents | RestartCount > 3 in 15 min | Sev2 |
| OOMKilled | KubeEvents | Reason == "OOMKilled" | Sev2 |
| Container CPU > 90% | Perf | CounterName == "cpuUsageNanoCores" sustained | Sev3 |
| Container Memory > 90% | Perf | CounterName == "memoryWorkingSetBytes" sustained | Sev3 |
| Pod not Ready | KubePodInventory | PodStatus != "Running" for > 5 min | Sev3 |

## Example Queries

```kql
// Recent errors from RP worker
ContainerLogV2
| where TimeGenerated > ago(1h)
| where PodName startswith "cleanroom-worker"
| where LogMessage contains "Error" or LogMessage contains "Exception"
| project TimeGenerated, PodName, ContainerName, LogMessage
| order by TimeGenerated desc

// OOMKilled events
KubeEvents
| where TimeGenerated > ago(24h)
| where Reason == "OOMKilled"
| project TimeGenerated, Name, Namespace, Message

// Container memory usage (right-sizing)
Perf
| where TimeGenerated > ago(1h)
| where ObjectName == "K8SContainer"
| where CounterName == "memoryWorkingSetBytes"
| summarize AvgMB=avg(CounterValue)/1024/1024, MaxMB=max(CounterValue)/1024/1024 by InstanceName
| order by MaxMB desc

// Pod restart history
KubePodInventory
| where TimeGenerated > ago(24h)
| where Namespace in ("cleanroom-ns", "frontendns", "consortiummanager-ns")
| where PodRestartCount > 0
| summarize MaxRestarts=max(PodRestartCount) by PodCreationTimeStamp, PodName, Namespace
| order by MaxRestarts desc
```

## Cost Considerations

Container Insights can be expensive at scale. Cost controls:

1. **Namespace filtering** — only collect from app namespaces, not kube-system
2. **Basic logs tier** for ContainerLogV2 — cheaper, shorter retention
3. **Sampling** — reduce collection interval from 1m to 5m if volume is high
4. **Transition plan** — once structured logging (Section 1.3.2) is live, consider disabling ContainerLogV2

## Dependencies

- Log Analytics workspace (same as Section 1.4)
- AKS add-on enablement via ARM/EV2
- Data Collection Rule configuration
- Cost approval
