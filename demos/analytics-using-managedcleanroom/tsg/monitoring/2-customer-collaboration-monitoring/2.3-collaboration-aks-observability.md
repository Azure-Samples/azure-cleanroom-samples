# 2.3 Collaboration AKS Cluster Observability

## Overview

Each customer collaboration gets its own AKS cluster. This section covers what observability exists inside those clusters and the challenges of monitoring them.

## Current State

| Component | Namespace | Status |
|-----------|-----------|--------|
| Prometheus (`prometheus-server`) | `telemetry` | Available ✅ |
| Grafana dashboards (`cleanroom-spark-grafana`) | `telemetry` | Available ✅ |
| Container Insights | — | Not available (blocked by deny assignments) |

## What's Already Deployed

### Prometheus

Deployed by the `EnableClusterObservability` task during collaboration creation. Collects:
- Cluster metrics (node CPU/memory, pod counts)
- Pod-level metrics (container CPU/memory, restarts)
- Spark metrics (executor count, task throughput)

### Grafana Dashboards

Pre-configured dashboards for:
- Spark query execution (executor timeline, task stages)
- Resource usage (CPU/memory per executor)
- Query history (rows read/written, duration)

Customer accesses via readonly kubeconfig + port-forward:
```bash
kubectl --kubeconfig collab-kubeconfig port-forward svc/cleanroom-spark-grafana 3000:80 -n telemetry
```

## The Challenge: Deny Assignments

Customer collaboration clusters are in MOBO-managed resource groups with **deny assignments**. This means:
- ❌ Can't enable Container Insights (requires modifying AKS addon config)
- ❌ Can't add Diagnostic Settings directly
- ❌ Can't create Log Analytics workspace connections
- ✅ Deny assignment excludes: RP MI, agentpool MI, cluster MI
- ✅ Customer has readonly kubeconfig (kubectl access)

### Workaround: Route Logs Through RP

Since the RP's managed identity is excluded from deny assignments, collaboration cluster logs can be routed through the RP's monitoring infrastructure:

```
Collaboration AKS cluster
  → cluster-provider-client (RP sidecar, excluded from deny)
    → Geneva sink
      → Kusto

Alternative:
  → Prometheus (already deployed in cluster)
    → Remote-write to central Prometheus/Grafana (if configured)
```

| Metric | Source | Purpose |
|--------|--------|---------|

| Pod restart count | Prometheus | Stability |
| Analytics namespace pod status | Monitoring worker | Health state bubbled up to ARM |
