# 3.1 Product Group Alerts (ICM)

## Overview

Alerts that fire when something is broken in the ACCR service and create an ICM incident for the on-call engineer. These are powered by Geneva/Kusto metrics and Container Insights.

## Current State

**Status: Planned** — No ICM alert rules configured yet. Geneva → Kusto pipeline is operational (prerequisite met).

## Alert Rules

### Service Availability (Sev1 — Page On-Call)

| Alert | Source | Condition | Evaluation | Action |
|-------|--------|-----------|------------|--------|
| RP Unavailable | Synthetic monitor | `/checkConnectionsInit` or ARM endpoint fails > 5 min | 1 min | Page on-call, check RP pods |
| Frontend Unavailable | Synthetic monitor | `/checkConnectionsInit` fails > 5 min | 1 min | Page on-call, check Frontend pods |
| CM Unavailable | Synthetic monitor | Health endpoint fails > 5 min | 1 min | Page on-call, check CM pods |

### Infrastructure Health (Sev2 — Alert Engineering)

| Alert | Source | Condition | Evaluation | Action |
|-------|--------|-----------|------------|--------|
| Pod CrashLoop | Container Insights (KubeEvents) | Pod restart count > 3 in 15 min | 5 min | Check pod logs, recent deployments |
| Worker OOM | Container Insights (KubeEvents) | OOMKilled event | Immediate | Increase memory limit (known: cluster-provider-client 200Mi→512Mi) |
| Node CPU High | Azure Monitor | Node CPU > 80% sustained 5 min | 1 min | Check workload, scale out |
| Node Memory High | Azure Monitor | Node memory > 85% sustained 5 min | 1 min | Check for memory leaks, scale out |

### Application Health (Sev2)

| Alert | Source | Condition | Evaluation | Action |
|-------|--------|-----------|------------|--------|
| Collaboration Create Failure Rate | Geneva metric | > 10% failures in 1 hour | 15 min | Check by region + task name |
| Collaboration Create P95 Duration | Geneva metric | P95 > 45 min (normal ~30 min) | 30 min | Investigate slow task |
| EnableWorkload Failure Rate | Geneva metric | > 10% failures in 1 hour | 15 min | Check CACI capacity by region |
| Frontend 5xx Rate | Geneva metric | > 5% in 5 min | 1 min | Check Frontend pod logs |

### Dependency Health (Sev2-3)

| Alert | Source | Condition | Evaluation | Action |
|-------|--------|-----------|------------|--------|
| MOBO MRG Creation Failure | RP Worker logs | InternalError from MOBO | Per occurrence | Check recovery handler, retry |
| RBAC Propagation Timeout | RP Worker logs | > 12 iterations (3 min) without success | Per occurrence | Check Azure RBAC service health |
| CACI Capacity Shortage | Cluster Provider logs | FailedCreatePodSandBox | Per occurrence | Check CACI capacity by region, open CRI ticket |
| VN2 Node Registration Failure | Cluster Provider logs | WaitForVN2NodeReady timeout | Per occurrence | Check K8s version pinning, VN2 service health |
| CCF Node Unhealthy | Consortium Manager | CCF health check fails | Per occurrence | Auto-recovery should handle; alert if recovery also fails |
| Attestation Failure | ccr-proxy logs | VerifySnpAttestationFailed (tag mismatch) | Per occurrence | Check image tags, security policy |
| Cosmos DB Throttling | Geneva/Cosmos metrics | 429 responses > 10 in 5 min | 5 min | Scale RUs or optimize queries |

## Implementation Plan

### Step 1: ICM Connector Setup

Configure Geneva → ICM connector for ACCR team:

```
Geneva Alert Rule
  → Action: ICM
    → Tenant: ACCR
    → Severity: {per alert}
    → Routing: ACCR On-Call
    → Auto-mitigate: Yes (for transient alerts)
```

### Step 2: Kusto Alert Rules

For alerts sourced from Kusto (after Geneva → Kusto):

```kql
// Example: Collaboration Create Failure Rate
let window = 1h;
CleanRoomOperations
| where Timestamp > ago(window)
| where WorkflowName == "CreateCollaborationWorkflow"
| where TaskName == "CreateCollaborationFinalize"
| summarize Total=count(), Failed=countif(Level == "Error") by Region
| where Total > 0
| extend FailureRate = round(100.0 * Failed / Total, 1)
| where FailureRate > 10
```

```kql
// Example: P95 duration regression
CleanRoomOperations
| where Timestamp > ago(1h)
| where WorkflowName == "CreateCollaborationWorkflow"
| where TaskName == "CreateCollaborationFinalize"
| where Level == "Information"
| summarize P95=percentile(DurationMs, 95) by Region
| where P95 > 2700000  // 45 min in ms
```

### Step 3: Container Insights Alert Rules

```json
{
  "type": "Microsoft.Insights/scheduledQueryRules",
  "apiVersion": "2023-03-15-preview",
  "name": "accr-pod-crashloop",
  "properties": {
    "severity": 2,
    "evaluationFrequency": "PT5M",
    "windowSize": "PT15M",
    "scopes": ["<log-analytics-workspace-id>"],
    "criteria": {
      "allOf": [
        {
          "query": "KubeEvents | where Reason == 'BackOff' | where Namespace in ('cleanroom-ns','frontendns','consortiummanager-ns') | summarize RestartCount=count() by Name, Namespace | where RestartCount > 3",
          "timeAggregation": "Count",
          "operator": "GreaterThan",
          "threshold": 0
        }
      ]
    },
    "actions": {
      "actionGroups": ["<action-group-id>"]
    }
  }
}
```

## Escalation Path

```
Alert Fires → ICM Incident Created
  → On-Call Engineer (Sev1: 15 min, Sev2: 1 hour)
    → Follow debugging workflow (Section 4.1)
      → Escalate to service owner if needed
```
