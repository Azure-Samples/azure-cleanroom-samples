# 3.2 Customer Alerts (Azure Monitor)

## Overview

Enable customers to create their own alerts on their `Microsoft.CleanRoom/Collaborations` ARM resource using standard Azure Monitor patterns. This is what customers expect from any Azure resource.

## Current State

**Status: Planned/TBD** — No custom metrics or resource logs exposed on the Collaboration ARM resource yet.

## What Customers Need

### Custom Metrics on Collaboration Resource

Expose metrics directly on the `Microsoft.CleanRoom/Collaborations` ARM resource so customers can create Azure Monitor metric alerts:

| Metric | Type | Values | Customer Use |
|--------|------|--------|-------------|
| `CollaborationHealthState` | Gauge | 0 = Ok, 1 = Error | Alert when health degrades |
| `QueryExecutionState` | Gauge | Per query job | Alert on query failure (TBD/Not Planned) |

### Resource Logs (Diagnostic Settings)

Enable Diagnostic Settings on `Microsoft.CleanRoom/Collaborations` so customers can route events to their own Log Analytics workspace:

| Log Category | Events Included | Use Case |
|-------------|----------------|----------|
| `CollaborationOperations` | Create, delete, enableWorkload, addCollaborator | Track lifecycle changes |
| `QueryExecution` | Query submit, state changes (SUBMITTED→RUNNING→COMPLETED/FAILED) | Monitor query pipeline |
| `AuditEvents` | CCF ledger events (governance actions, votes, proposals) | Compliance/audit trail |
| `HealthEvents` | Health state changes with `healthIssues` details | Proactive health monitoring |

### Example: Customer Alert Configuration

```json
{
  "type": "Microsoft.Insights/metricAlerts",
  "name": "collab-health-alert",
  "properties": {
    "severity": 2,
    "scopes": [
      "/subscriptions/{sub}/resourceGroups/{rg}/providers/Microsoft.CleanRoom/collaborations/{name}"
    ],
    "criteria": {
      "odata.type": "Microsoft.Azure.Monitor.SingleResourceMultipleMetricCriteria",
      "allOf": [
        {
          "name": "HealthDegraded",
          "metricName": "CollaborationHealthState",
          "operator": "GreaterThan",
          "threshold": 0,
          "timeAggregation": "Maximum"
        }
      ]
    },
    "actions": [
      {
        "actionGroupId": "/subscriptions/{sub}/resourceGroups/{rg}/providers/Microsoft.Insights/actionGroups/{customer-action-group}"
      }
    ]
  }
}
```

## Implementation Plan

### Step 1: Emit Custom Metrics from RP

The RP needs to emit custom metrics on the Collaboration ARM resource using the Azure Monitor custom metrics API:

```
POST https://{region}.monitoring.azure.com/subscriptions/{sub}/resourceGroups/{rg}/providers/Microsoft.CleanRoom/collaborations/{name}/metrics
```

### Step 2: Implement Resource Log Provider

Add Diagnostic Settings support to the `Microsoft.CleanRoom` resource provider:
- Register log categories (`CollaborationOperations`, `QueryExecution`, `AuditEvents`, `HealthEvents`)
- Emit events when operations occur
- Support customer-configured destinations (Log Analytics, Storage, Event Hub)

### Step 3: Documentation

Publish customer-facing docs:
- How to enable Diagnostic Settings on Collaborations
- Recommended alert rules
- Example Kusto queries for resource logs

## Dependencies

- ARM resource provider support for custom metrics
- Diagnostic Settings implementation in the RP
- Customer documentation
