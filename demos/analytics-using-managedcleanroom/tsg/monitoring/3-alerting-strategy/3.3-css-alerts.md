# 3.3 CSS (Support) Alerts

## Overview

CSS (Customer Support Services) needs to triage customer tickets without always escalating to engineering. They need access to the same telemetry and proactive alerting for common issues.

## Current State

**Status: Planned** — CSS currently escalates to engineering for most issues. No proactive CSS-specific alerts exist.

## CSS Access Model

CSS engineers get access to the engineering Kusto database via **security group membership**. Same Geneva → Kusto pipeline, same queries as engineering. No separate data pipeline needed.

```
CSS Engineer
  → Added to ACCR-CSS security group
    → Grants read access to ACCR Kusto cluster
      → Same tables: CleanRoomOperations, ACCRMetrics, etc.
```

## Proactive CSS Alerts

| Alert | Source | Condition | Action | Priority |
|-------|--------|-----------|--------|----------|
| Collaboration stuck in Provisioning | RP Worker telemetry | `provisioningState == Provisioning` > 60 min | Proactive customer outreach ("we're aware, investigating") | Planned |
| Query stuck in SUBMITTED | Frontend Service telemetry + RP monitoring | Query in `SUBMITTED` state > 15 min | CACI capacity or scheduling issue — check region | Planned |
| EnableWorkload failure | RP Worker telemetry | `EnableWorkloadWorkflow` failure | Quota or capacity issue — check customer subscription | Planned |
| Multiple failures in same region | Geneva aggregation | > 3 distinct collaboration failures in same region in 1 hour | Regional platform issue — escalate to engineering | Planned |

## CSS Triage Workflow

```
Customer Ticket Received
  │
  ├── 1. Check Azure Portal
  │     → Collaboration resource: provisioningState, healthState, healthIssues
  │     → Activity Log on collaboration RG: ARM operation history, error details
  │
  ├── 2. Customer TSG Issue Matrix
  │     → Map symptom to known issue (#1-23 in Customer TSG)
  │     → Follow resolution steps
  │
  ├── 3. Kusto Query (via security group access)
  │     → Query CleanRoomOperations for operation history
  │     → Check by subscriptionId, collaborationName, timeframe
  │
  └── 4. Escalate to Engineering
        → Provide: subscriptionId, collaborationName, operationId, timeframe
        → Link to relevant Kusto query results
```

## Key Kusto Queries for CSS

```kql
// Customer collaboration status
CleanRoomOperations
| where SubscriptionId == "{customer-sub-id}"
| where CollaborationName == "{collab-name}"
| where Timestamp > ago(24h)
| project Timestamp, TaskName, Level, Message, DurationMs
| order by Timestamp desc

// All failures for a customer in last 7 days
CleanRoomOperations
| where SubscriptionId == "{customer-sub-id}"
| where Level == "Error"
| where Timestamp > ago(7d)
| project Timestamp, CollaborationName, TaskName, ExceptionType, Message
| order by Timestamp desc

// Regional health check
CleanRoomOperations
| where Timestamp > ago(1h)
| where Level == "Error"
| summarize FailCount=count() by Region, TaskName
| order by FailCount desc
```
