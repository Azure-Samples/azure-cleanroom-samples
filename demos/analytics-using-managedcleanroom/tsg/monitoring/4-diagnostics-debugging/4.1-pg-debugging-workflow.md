# 4.1 Product Group Debugging Workflow

## Overview

Step-by-step debugging workflow for engineering when investigating issues with ACCR services. Follows a top-down approach: ARM → RP → SyncOps → Sidecars → Customer Cluster.

## Debugging Flow

```
Issue Reported (ICM / Customer Ticket / Alert)
    │
    ├─── 1. ARM Activity Log
    │       → Check ARM operation status
    │       → Get operationId for correlation
    │       → Look for provisioning failures on sub-resources
    │
    ├─── 2. RP Worker Logs (Kusto)
    │       → Match by operationId from ARM
    │       → Check workflow state: which task was running?
    │       → Filter by collaborationName, subscriptionId
    │
    ├─── 3. SyncOps Worker Logs (Kusto)
    │       → For long-running operations (CreateCluster, CCF, MOBO)
    │       → SyncOps pod has 6 containers — check the right one:
    │       │
    │       ├── cleanroominternalapi  → Internal API calls
    │       ├── ccf-provider-client   → CCF/CACI operations
    │       ├── cluster-provider-client → AKS cluster operations
    │       ├── cgs-client            → Contract governance
    │       ├── cleanroom-client      → Clean room operations
    │       └── cleanroominternalapi  → Internal API
    │
    ├─── 4. Frontend Service Logs (Kusto)
    │       → Frontend API errors, auth failures
    │       → Check by endpoint, status code, correlationId
    │
    ├─── 5. Consortium Manager Logs (Kusto)
    │       → CCF network operations
    │       → Node health, recovery events
    │
    ├─── 6. Customer Collaboration Cluster
    │       → Use getReadonlyKubeConfig API
    │       → kubectl get pods -A (check all namespaces)
    │       → kubectl logs <pod> -n analytics (Spark driver logs)
    │       → kubectl describe pod <pod> (events, resource limits)
    │       → Port-forward to Grafana for Spark execution details
    │
    ├─── 7. Cosmos DB (State/Membership)
    │       → Account: cleanroomdbgbl-{env}
    │       → DB: ServiceDatabase, Container: userscontainer
    │       → Auth: AAD token (local auth disabled)
    │       → Check collaboration state, membership mappings
    │
    └─── 8. ARM Activity Log (Managed RGs)
            → Collab MRG: CleanRoom_Collaborations_{name}
            │   → AKS, VNet, Public IP, NAT Gateway, UAMI, Private DNS
            → Consortium MRG: CleanRoom_consortiums_ccf-{name}
                → CACI container groups (×3), Storage, UAMI, Key Vault
```

## Quick Reference: Which Log to Check

| Symptom | Check First | Then Check |
|---------|------------|------------|
| Collaboration stuck in Provisioning | RP Worker logs → current task | SyncOps → specific container for that task |
| enableWorkload failed | RP Worker → EnableWorkloadWorkflow | SyncOps → cluster-provider-client, ccf-provider-client |
| Query failed (SUBMISSION_FAILED) | Frontend logs → SubmitQuery | Collaboration cluster → analytics namespace pods |
| Query failed (FAILED) | Collaboration cluster → Spark driver logs | Grafana → Spark execution dashboard |
| Health state Error | RP monitoring worker logs | Collaboration cluster → kubectl get pods -A |
| CCF/Consortium issues | CM logs | SyncOps → ccf-provider-client |
| Auth failures | Frontend → AuthFailure metric | Frontend logs → auth errors |
| CACI deployment failure | SyncOps → cluster-provider-client | ARM Activity Log → Consortium MRG |

## Common Investigation Patterns

### Pattern 1: Find All Operations for a Collaboration

```kql
CleanRoomOperations
| where CollaborationName == "{name}"
| where Timestamp > ago(7d)
| project Timestamp, Service, WorkflowName, TaskName, Level, DurationMs, Message
| order by Timestamp asc
```

### Pattern 2: Correlate Across Services

```kql
// Find the ARM operationId, then trace through all services
CleanRoomOperations
| where OperationId == "{arm-operation-id}"
| project Timestamp, Service, TaskName, Level, Message
| order by Timestamp asc
```

### Pattern 3: Find Failures by Region

```kql
CleanRoomOperations
| where Timestamp > ago(24h)
| where Level == "Error"
| summarize Count=count(), Tasks=make_set(TaskName), Exceptions=make_set(ExceptionType) by Region
| order by Count desc
```

### Pattern 4: Task Duration Regression

```kql
// Compare this week vs last week
let thisWeek = CleanRoomOperations | where Timestamp > ago(7d) | where DurationMs > 0;
let lastWeek = CleanRoomOperations | where Timestamp between(ago(14d)..ago(7d)) | where DurationMs > 0;
thisWeek
| summarize ThisP95=percentile(DurationMs, 95) by TaskName
| join kind=leftouter (lastWeek | summarize LastP95=percentile(DurationMs, 95) by TaskName) on TaskName
| extend Regression = round((ThisP95 - LastP95) / LastP95 * 100, 1)
| where Regression > 20  // > 20% slower
| order by Regression desc
```
