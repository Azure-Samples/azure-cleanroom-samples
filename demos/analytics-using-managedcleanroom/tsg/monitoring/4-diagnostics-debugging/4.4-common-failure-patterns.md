# 4.4 Common Failure Patterns

## Overview

Documented failure patterns from ACCR operational history. Each pattern includes the root cause, how it was detected, the fix, and how to prevent recurrence.

## Failure Patterns

### 1. MOBO InternalError

| | |
|---|---|
| **Symptom** | Collaboration creation fails at `CreateManagedResourceGroup` task |
| **Root Cause** | MOBO (Managed-On-Behalf-Of) service returns intermittent `InternalError` |
| **Detection** | RP Worker logs: `ARM InternalError on MRG creation` |
| **Fix** | Recovery handler checks if MRG already exists before retrying. If MRG exists, skip creation and proceed. |
| **Status** | Fixed ✅ (canaryConsort9 incident) |
| **Prevention** | Recovery handler is permanent. No action needed. |

### 2. RBAC Propagation Race

| | |
|---|---|
| **Symptom** | 403 Forbidden on role assignment operations after creating resources |
| **Root Cause** | Azure RBAC is eventually consistent — role assignments aren't immediately effective |
| **Detection** | RP Worker logs: RBAC propagation retry count |
| **Fix** | `WaitForRbacPropagation` loop: 12 iterations × 15 seconds, checking all 3 required roles |
| **Status** | Fixed ✅ |
| **Prevention** | Built into workflow. Future enhancement: increase to 20 iterations with exponential backoff (Section 6.2). |

### 3. VN2 Kubernetes Version Mismatch

| | |
|---|---|
| **Symptom** | VN2 (Virtual Node v2) fails to register with AKS cluster |
| **Root Cause** | AKS default K8s version exceeds VN2 kubelet's supported version |
| **Detection** | `WaitForVN2NodeReady` timeout in cluster-provider-client |
| **Fix** | Pin K8s version to 1.33 (or latest VN2-compatible version). Added `WaitForVN2NodeReady` check. |
| **Status** | Fixed ✅ |
| **Prevention** | K8s version pinned in ARM template. Monitor VN2 version support announcements. |

### 4. NRMS NSG Blocking Frontend→Analytics

| | |
|---|---|
| **Symptom** | Frontend Service can't reach analytics endpoint; queries time out |
| **Root Cause** | NRMS (Network Resource Management Service) auto-applies restrictive NSG to collaboration VNet, blocking inbound HTTPS |
| **Detection** | Frontend logs: connection timeout to analytics endpoint |
| **Fix** | `UpdateWorkloadNsgRulesTask` adds `AllowInternetInboundHttps` rule to override NRMS NSG |
| **Status** | Fixed ✅ |
| **Prevention** | Task runs automatically during EnableWorkload workflow. |

### 5. Consortium Null Endpoints

| | |
|---|---|
| **Symptom** | `PrepareConsortiumTask` fails with NullReferenceException on consortium endpoints |
| **Root Cause** | Code treated ARM resource existence as success; didn't check `provisioningState`. Resource existed but endpoints were null because provisioning was still in progress. |
| **Detection** | RP Worker logs: NPE in PrepareConsortiumTask |
| **Fix** | Check `provisioningState == Succeeded` before reading endpoints |
| **Status** | Fixed ✅ (canaryConsort9 incident) |
| **Prevention** | Code fix is permanent. Added validation for all ARM resource reads. |

### 6. cluster-provider-client OOM

| | |
|---|---|
| **Symptom** | SyncOps pod restarts; cluster-provider-client container OOMKilled |
| **Root Cause** | Memory limit set to 200Mi was too low for AKS cluster operations |
| **Detection** | KubeEvents: `Reason == OOMKilled`, container `cluster-provider-client` |
| **Fix** | Increased memory limit from 200Mi to 512Mi |
| **Status** | Fixed ✅ |
| **Prevention** | Monitor container memory usage via Container Insights (Section 1.5). Set alerts on OOMKilled events. |

### 7. Prometheus NFS Blocked by Deny Assignment

| | |
|---|---|
| **Symptom** | `prometheus-server` pod stuck in Pending in collaboration cluster |
| **Root Cause** | EnableClusterObservability ran after deny assignment was applied. Prometheus tried to create PVC but deny assignment blocked it. |
| **Detection** | Collaboration cluster: pod in Pending state, PVC not bound |
| **Fix** | Reordered workflow: `CreateCluster` → `UpdateClusterDenyAssignments` → `EnableClusterObservability`. Observability is installed before deny assignments lock down the cluster. |
| **Status** | Fixed ✅ |
| **Prevention** | Workflow ordering is enforced in code. |

### 8. Helm Upgrade Kills Active Operations

| | |
|---|---|
| **Symptom** | SyncOps worker pod restarts during helm upgrade, aborting in-progress provisioning operations |
| **Root Cause** | Helm upgrade recreates pods by default. If a provisioning operation is in progress, it gets aborted mid-way. |
| **Detection** | RP Worker logs: operation aborted unexpectedly |
| **Fix** | Operational procedure: never deploy during active provisioning. Set `maxSurge: 0` to prevent parallel pod creation during rolling updates. |
| **Status** | Documented ✅ (operational procedure) |
| **Prevention** | Deployment checklist: verify no active provisioning operations before helm upgrade. Future: drain operations before upgrade. |

## Pattern Detection Queries

```kql
// Detect MOBO failures
CleanRoomOperations
| where Timestamp > ago(24h)
| where TaskName == "CreateManagedResourceGroupTask"
| where Level == "Error"
| summarize Count=count() by Region, ExceptionType
| order by Count desc

// Detect OOM events
KubeEvents
| where Timestamp > ago(24h)
| where Reason == "OOMKilled"
| where Namespace in ("cleanroom-ns", "frontendns", "consortiummanager-ns")
| project Timestamp, Name, Namespace, Message

// Detect RBAC propagation issues (high retry count)
CleanRoomOperations
| where Timestamp > ago(24h)
| where TaskName == "WaitForRbacPropagation"
| where DurationMs > 120000  // > 2 min means many retries
| project Timestamp, CollaborationName, DurationMs, Region

// Detect VN2 registration failures
CleanRoomOperations
| where Timestamp > ago(24h)
| where TaskName == "WaitForVN2NodeReady"
| where Level == "Error"
| project Timestamp, CollaborationName, Region, Message
```

## Adding New Patterns

When a new failure pattern is identified:
1. Document it here with the same format (Symptom, Root Cause, Detection, Fix, Status, Prevention)
2. Add a detection query
3. If recurring, create an alert rule (Section 3.1)
4. Update the Customer TSG if customer-impacting
