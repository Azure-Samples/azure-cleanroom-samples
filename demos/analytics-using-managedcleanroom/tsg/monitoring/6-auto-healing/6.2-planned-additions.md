# 6.2 Planned Auto-Healing Additions

## Overview

Planned enhancements to self-recovery capabilities. These build on the existing patterns (Section 6.1) to handle more failure scenarios automatically.

## Planned Additions

### 1. Enhanced RBAC Retry with Exponential Backoff

| | |
|---|---|
| **Current** | 12 iterations × 15 seconds (3 min total, linear) |
| **Proposed** | 20 iterations with exponential backoff (15s → 30s → 60s → ..., ~10 min total) |
| **Why** | Some regions have slower RBAC propagation. 3 min timeout occasionally insufficient. |
| **Complexity** | Low — code change in `WaitForRbacPropagation` |
| **Status** | Planned |

```csharp
// Proposed implementation
int maxRetries = 20;
for (int i = 0; i < maxRetries; i++)
{
    if (await CheckAllRolesAsync())
        return;
    int delaySeconds = Math.Min(15 * (int)Math.Pow(2, i / 3), 120); // Cap at 2 min
    await Task.Delay(TimeSpan.FromSeconds(delaySeconds));
}
```

### 2. Auto-Recover Stuck Provisioning State

| | |
|---|---|
| **Current** | Collaboration stays in `Provisioning` indefinitely if workflow fails silently |
| **Proposed** | Monitoring worker detects `Provisioning` > 60 min, checks underlying resources, and either completes or fails the collaboration |
| **Why** | Prevents collaborations from being permanently stuck |
| **Complexity** | Medium — needs careful logic to determine correct final state |
| **Status** | TBD / Not Planned |

Logic:
```
If provisioningState == Provisioning for > 60 min:
  1. Check if AKS cluster exists and is healthy → if yes, finalize as Succeeded
  2. Check if AKS cluster exists but unhealthy → set healthState = Error
  3. Check if AKS cluster doesn't exist → set provisioningState = Failed
  4. Log recovery action for audit trail
```

**Risk:** Auto-recovering at the wrong time could corrupt state. Needs thorough testing.

### 3. Auto-Cleanup Orphaned MRGs

| | |
|---|---|
| **Current** | If collaboration deletion fails, managed RGs (`CleanRoom_Collaborations_*`, `CleanRoom_consortiums_*`) may be orphaned |
| **Proposed** | Periodic scan for `CleanRoom_*` RGs without a parent collaboration resource |
| **Why** | Orphaned MRGs consume resources and cost money |
| **Complexity** | Medium — need to safely identify truly orphaned vs in-progress |
| **Status** | TBD / Not Planned |

Safety constraints:
- Only clean up MRGs older than 24 hours (avoid deleting in-progress creations)
- Verify no active ARM locks or deny assignments preventing deletion
- Log all cleanup actions
- Dry-run mode first

### 4. Auto-Upgrade Collaboration Cluster Images

| | |
|---|---|
| **Current** | Collaboration AKS clusters use the image versions from creation time |
| **Proposed** | Coordinated rolling update of collaboration cluster images during maintenance windows |
| **Why** | Security patches, bug fixes, feature updates |
| **Complexity** | High — needs coordination across active clusters, drain operations first |
| **Status** | TBD / Not Planned |

Challenges:
- Can't upgrade during active provisioning (helm upgrade kills operations — pattern #8)
- Need to drain active operations before upgrade
- Need rollback mechanism if upgrade fails
- Customer impact: query execution may be briefly interrupted

### 5. Health State Auto-Recovery

| | |
|---|---|
| **Current** | `healthState = Error` persists until manual intervention or pod self-heals |
| **Proposed** | Monitoring worker attempts to restart unhealthy pods in collaboration cluster |
| **Why** | Many pod failures are transient and resolve with a restart |
| **Complexity** | Medium — need to avoid restart loops |
| **Status** | TBD / Not Planned |

Safety constraints:
- Only restart pods that have been unhealthy for > 10 minutes
- Maximum 3 restart attempts per pod per hour
- Don't restart pods in the middle of Spark execution
- Log all restart actions

## Priority Ranking

| Addition | Impact | Complexity | Recommendation |
|----------|--------|------------|---------------|

| Health state auto-recovery | Medium | Medium | Evaluate after above |
| Auto-upgrade images | High (security) | High | Long-term roadmap |
