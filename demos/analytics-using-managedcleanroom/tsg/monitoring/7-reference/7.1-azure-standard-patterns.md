# 7.1 Azure Standard Patterns Used

## Overview

Reference of Azure-standard monitoring patterns used by ACCR and their implementation status.

## Patterns

| Pattern | Description | ACCR Implementation | Status |
|---------|-------------|-------------------|--------|
| **Platform Metrics** | Azure Monitor auto-collected metrics for AKS | Node CPU/memory, pod counts, API server health on all 3 AME clusters | Planned (Section 1.1) |
| **Resource Logs** | Diagnostic Settings → Log Analytics | AKS control plane logs (kube-audit-admin, kube-apiserver, etc.) | Planned (Section 1.4) |
| **Activity Log** | Automatic for ARM resources | Already collected for Collaboration CRUD, MRG operations | Available ✅ |
| **Container Insights** | AKS add-on for container telemetry | ContainerLogV2, KubeEvents, Perf for AME clusters | Planned (Section 1.5) |
| **Prometheus + Grafana** | Managed Prometheus + Grafana | Prometheus deployed in collaboration clusters. Grafana with pre-built Spark dashboards | Available ✅ (Prometheus) / Planned (enhancements) |
| **Resource Health** | Azure Resource Health for ARM resources | Add for `Microsoft.CleanRoom/Collaborations` resource type | TBD / Not Planned |
| **Recommended Alerts** | Alert rule templates (like AKS provides) | Create for `Microsoft.CleanRoom/Collaborations` resource type | Planned |
| **Geneva / MDM** | AME standard for 1P service metrics | Custom metrics via OTLP → ILB → Geneva DaemonSet on all 3 clusters | Available ✅ (pipeline), Planned (instrumentation) |
| **Geneva → Kusto** | AME standard for log analysis | Logs + Metrics → Kusto for debugging, alerts, dashboards | Available ✅ (Vaiddhe/Yash) |
| **ICM** | AME standard for incident management | Alert → ICM routing for engineering on-call | Planned (Section 3.1) |
| **Application Insights** | OpenTelemetry-based APM | Optional for Frontend Service — dependency tracking, live metrics | TBD / Not Planned (Section 1.3.3) |
| **Custom Metrics on ARM Resource** | Expose metrics on ARM resource for customer alerting | `CollaborationHealthState` on Collaboration resource | TBD (Section 3.2) |
| **Resource Logs on ARM Resource** | Diagnostic Settings on ARM resource for customer log routing | CollaborationOperations, QueryExecution, AuditEvents, HealthEvents | Planned (Section 3.2) |
| **Synthetic Monitors** | Automated endpoint availability probes | RP, Frontend, CM availability + BVT + Longhaul | Planned (Section 1.2) |
